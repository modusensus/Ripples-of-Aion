# 期望的 CyreneCore Memory API 最小能力清单

> 提交方：岁月涟漪 / Ripples of Aion（github.com/modusensus/Ripples-of-Aion）
> 背景对话：Playa-0v0/Cyrene-Plugins#1（2026-09 作者与维护者关于 Memory API 方向的讨论）
> 定位：以一个真实运行的并行记忆层插件（自有 JSONL 存储 + 自管检索 + 实体属性时间轴）
> 的实际需求为输入，供核心 Memory API 设计时参考。清单刻意保持最小——只列插件
> 无法自管、必须依赖核心的部分。

## A. 查询（读）

| # | 能力 | 说明 |
|---|------|------|
| A1 | 文本检索 | 按文本查询记忆，返回 N 条 + 相关度。关键词起步即可；核心若已有语义/RAG 检索则直接复用 |
| A2 | 过滤条件 | 按会话 id、创建时间范围、来源插件 id 过滤 |
| A3 | 实体属性时间轴读取 | 给定 entity（可选 attribute），返回按时间排序的声明：`entity / attribute / value / validFrom / validUntil / createdAt`，并提供「当前有效值」的判定语义（validUntil 为空的最新一条） |
| A4 | Provenance 必带 | 检索结果携带来源插件 id、会话/轮次引用、创建时间——插件侧的可视化（时间轴/图谱）依赖它 |
| A5 | 读路径性能契约 | 同步、可分页/限条数，单次调用满足 prompt provider 的 2 秒红线（`provide()` 只做快读拼接） |

## B. 写入

| # | 能力 | 说明 |
|---|------|------|
| B1 | 建议写入 | 插件提交记忆（content + 可选实体属性声明 + provenance），由核心做校验、去重、索引同步 |
| B2 | 管理自身记忆 | 更新、软删**仅限本插件创建**的记录（按 plugin id 归属校验，越权拒绝） |
| B3 | 幂等写入 | 支持内容哈希/外部引用键，事件重放、多来源重复投递不产生重复记忆 |
| B4 | 时间轴闭合语义 | 同 (entity, attribute) 写入新值时，提供「闭合旧值」的原语或钩子（旧值 validUntil 自动置为新值生效时间），而非直接覆盖——冲突历史正是知识页「信息演变」的原料 |

## C. 权限分层

1. **只读**——第一批提供就够大量插件使用；
2. **写入/管理自己创建的记忆**——默认归属边界；
3. **经用户明确授权后管理其他记忆**——未来扩展，需用户在 UI 显式授予。

## D. 事件（可选）

- 记忆变更事件（created / updated / deleted）：供插件同步自己的二级索引与可视化视图，避免轮询。

## E. 非目标

- 插件不要求直接访问核心的存储文件或数据库，一切经由 API；
- heat / 激活度 / 记忆策略由插件自管，不要求核心提供；
- 检索排序的算法偏好（关键词权重、向量模型）由插件自管，核心只保证基本检索能力与稳定性。
